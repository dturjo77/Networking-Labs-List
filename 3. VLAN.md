**Lab Name:** VLAN Configuration and Trunking (Inter-Switch VLAN Propagation)

### 1. Lab Objective
This lab aims to create multiple VLANs on two switches, assign access ports to specific VLANs, and configure a trunk link between the switches to allow VLAN traffic to propagate across devices.

**Skills/Concepts Practiced:**
- VLAN creation and naming
- Access port configuration
- Trunk port configuration (802.1Q)
- Understanding how VLANs segment broadcast domains
- Verifying VLAN propagation across switches via trunk links

### 2. Concept Explanation (In-depth)

**What is a VLAN?**  
A Virtual Local Area Network (VLAN) is a logical segmentation of a physical network. It groups devices into separate broadcast domains even if they are connected to the same physical switch.

**Why VLANs are used in real networks?**  
- To improve security by isolating sensitive departments
- To reduce broadcast traffic and enhance performance
- To organize the network logically according to departments, functions, or user types rather than physical location

**How VLANs work internally (simple explanation):**  
When a switch receives a frame, it checks the VLAN ID (assigned to the ingress port). The frame is forwarded only to ports that belong to the same VLAN. For traffic to cross switches, trunk ports tag frames with a VLAN ID using the 802.1Q protocol.

**Broadcast Domain Concept:**  
A broadcast domain is the set of devices that receive broadcast frames from each other. VLANs create multiple broadcast domains on a single switch.

**Real-world example:**  
In an office building:
- VLAN 10 (IT Department) – Servers and IT staff PCs
- VLAN 20 (HR Department) – HR computers and printers
- VLAN 30 (Customer Service) – Support team devices  
Even if all are connected to the same switches, they cannot communicate directly without a router (inter-VLAN routing).

**How switches handle VLANs internally:**  
Switches maintain a VLAN database and a MAC address table per VLAN. Frames are tagged on trunk links so the receiving switch knows which VLAN they belong to.

**Difference between VLAN and Physical Segmentation:**  
VLANs provide logical separation on shared hardware (cheaper and flexible), while physical segmentation requires separate switches for each group (more expensive but more isolated).

**Key Advantages:**
- Better security and traffic control
- Reduced unnecessary broadcast traffic
- Flexible network design
- Easier moves, adds, and changes

**Limitations:**
- Requires careful planning to avoid misconfiguration
- Inter-VLAN communication needs a Layer 3 device (Router or L3 Switch)

### 4. Step-by-Step Configuration

#### Switch 1 Configuration
```bash
Switch>enable
Switch#configure terminal

Switch(config)#vlan 10
Switch(config-vlan)#name IT                 // Creates VLAN 10 and assigns a meaningful name for easy identification

Switch(config-vlan)#vlan 20
Switch(config-vlan)#name HR                 // Creates VLAN 20 for HR department

Switch(config-vlan)#vlan 30
Switch(config-vlan)#name CS                 // Creates VLAN 30 for Customer Service

Switch(config-vlan)#exit

Switch(config)#interface range fa0/1-2
Switch(config-if-range)#switchport mode access      // Sets ports as access ports (carries traffic for one VLAN only)
Switch(config-if-range)#switchport access vlan 10   // Assigns these ports to VLAN 10 (IT)
Switch(config-if-range)#exit

Switch(config)#interface range fa0/3-4
Switch(config-if-range)#switchport mode access
Switch(config-if-range)#switchport access vlan 20   // Assigns to HR VLAN
Switch(config-if-range)#exit

Switch(config)#interface range fa0/5-6
Switch(config-if-range)#switchport mode access
Switch(config-if-range)#switchport access vlan 30   // Assigns to CS VLAN
Switch(config-if-range)#exit

Switch(config)#interface fa0/7
Switch(config-if)#switchport mode trunk             // Configures the port as a trunk to carry multiple VLANs to another switch
Switch(config-if)#exit

Switch(config)#do write                             // Saves the configuration
```

#### Switch 2 Configuration
```bash
Switch>enable
Switch#configure terminal

Switch(config)#vlan 10
Switch(config-vlan)#name IT

Switch(config-vlan)#vlan 20
Switch(config-vlan)#name HR

Switch(config-vlan)#vlan 30
Switch(config-vlan)#name CS

Switch(config-vlan)#exit

Switch(config)#interface range fa0/1-2
Switch(config-if-range)#switchport mode access
Switch(config-if-range)#switchport access vlan 30   // CS VLAN on these ports

Switch(config)#interface range fa0/3-4
Switch(config-if-range)#switchport mode access
Switch(config-if-range)#switchport access vlan 10   // IT VLAN

Switch(config)#interface range fa0/5-6
Switch(config-if-range)#switchport mode access
Switch(config-if-range)#switchport access vlan 20   // HR VLAN

Switch(config)#interface fa0/7
Switch(config-if)#switchport mode trunk             // Trunk port for inter-switch connectivity
Switch(config-if)#exit

Switch(config)#do write
```

### 5. Verification and Results

**Verification Commands:**

**On both switches:**
- `show vlan brief` → Displays VLANs and assigned ports
- `show interfaces trunk` → Verifies trunk status, allowed VLANs, and native VLAN
- `show interfaces fa0/7 switchport` → Checks trunk operational mode

**Expected Result:**
- VLANs 10, 20, and 30 created and active on both switches
- Correct ports assigned to respective VLANs
- Trunk link on Fa0/7 carrying VLANs 1,10,20,30
- Devices in the same VLAN (even across switches) can communicate at Layer 2

**Actual Result Meaning:**  
Successful trunk negotiation and VLAN propagation confirm that the switches are correctly segmenting traffic while allowing same-VLAN communication across the trunk link.

### 6. Troubleshooting

**Problems Faced & Solutions:**

1. **Problem:** Line protocol on Fa0/7 went down temporarily  
   **Cause:** Occurs during mode change from access to trunk  
   **Fix:** Normal behavior; link came back up after configuration.

2. **Problem:** Ports not assigned to correct VLAN  
   **Cause:** Forgetting to set `switchport mode access` before assigning VLAN  
   **Fix:** Always set mode first, then assign VLAN.

3. **Problem:** VLANs not propagating to Switch 2  
   **Cause:** Trunk not configured or trunk mode mismatch  
   **Fix:** Ensure both ends are in `switchport mode trunk`.

4. **Problem:** Devices in same VLAN cannot communicate across switches  
   **Cause:** Missing trunk or VLAN not allowed on trunk  
   **Fix:** Verify with `show interfaces trunk`.

### 7. Conclusion
This lab successfully demonstrated VLAN creation, port assignment, and trunk configuration for logical network segmentation across multiple switches. The key learning is how VLANs provide flexible, secure, and efficient network segmentation without requiring separate physical infrastructure.

### Notes / Real-World Insight
- Always use meaningful VLAN names in production.
- Standard practice: Use VLAN 1 as native VLAN or change it for security.
- In enterprise networks, VLANs are combined with VTP (VLAN Trunking Protocol) or manually configured on each switch for better control.
- Best practice: Document VLAN usage (e.g., VLAN 10 = Servers, VLAN 20 = Users, VLAN 99 = Management).
- For communication between different VLANs, inter-VLAN routing (Router-on-a-Stick or Layer 3 Switch) is required.
