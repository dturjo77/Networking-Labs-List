# VLAN Configuration, Trunking, and Port Security Lab

## Lab Objective

This lab demonstrates the configuration of **VLANs**, **trunk links**, and **port security best practices** on Cisco switches. Students will segment network traffic using VLANs, ensure proper inter-switch connectivity via trunks with VLAN pruning, and secure unused switch ports.

### Skills/Concepts Practiced
- Creating and naming VLANs
- Assigning access ports to VLANs
- Configuring 802.1Q trunk ports with allowed VLAN lists
- Securing unused ports (blackhole VLAN + shutdown)
- Verification using `show vlan`, `show interfaces trunk`, and connectivity testing

---

## Concept Explanation (Practical)

**What is it?**  
VLANs (Virtual Local Area Networks) logically segment a physical switch into multiple broadcast domains. Trunk ports carry traffic for multiple VLANs between switches using 802.1Q tagging.

**Why it is used in real networks?**  
To improve security, reduce broadcast traffic, and organize users by department (e.g., HR, Finance, IT) without requiring separate physical switches.

**How it works (simple):**  
- Access ports belong to one VLAN and send/receive untagged frames.
- Trunk ports add a VLAN tag (802.1Q) to frames so the receiving switch knows which VLAN the traffic belongs to.
- Unused ports are placed in a "blackhole" VLAN (999) and shut down to prevent unauthorized access.

**Real-world example:**  
In a company, HR employees are in VLAN 20, IT in VLAN 30, and CS in VLAN 10. Even though they are connected to the same switches, they cannot communicate directly without a router (inter-VLAN routing).

**Advantages:**
- Broadcast containment
- Enhanced security
- Logical organization

**Limitations:**
- Requires careful trunk configuration to avoid VLAN leakage
- Spanning Tree Protocol (STP) runs per VLAN

## Step-by-Step Configuration

### 🔹 Switch 1 (SW1)

```bash
Switch> enable
Switch# configure terminal
```

**1. Create VLANs**
```bash
Switch(config)# vlan 10
Switch(config-vlan)# name CS
Switch(config-vlan)# vlan 20
Switch(config-vlan)# name HR
Switch(config-vlan)# vlan 30
Switch(config-vlan)# name IT
Switch(config-vlan)# vlan 999
Switch(config-vlan)# name HACKER
Switch(config-vlan)# exit
```
*Explanation:* Creates the required VLANs. VLAN 999 acts as a blackhole VLAN for unused ports.

**2. Configure Access Ports**
```bash
Switch(config)# interface fa0/4
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config-if)# exit

Switch(config)# interface fa0/5
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 30
Switch(config-if)# exit

Switch(config)# interface fa0/6
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 20
Switch(config-if)# exit
```
*Explanation:* Assigns specific ports to their respective VLANs based on connected devices.

**3. Secure Unused Ports**
```bash
Switch(config)# interface range fa0/7 - 24 , gigabitEthernet 0/1 - 2
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 999
Switch(config-if-range)# shutdown
Switch(config-if-range)# exit
```
*Explanation:* Places all unused ports into the HACKER VLAN and shuts them down — a key security practice to prevent unauthorized plugging into the network.

**4. Configure Trunk Ports to SW2**
```bash
Switch(config)# interface range fa0/1 - 3
Switch(config-if-range)# switchport mode trunk
Switch(config-if-range)# switchport trunk allowed vlan except 999
Switch(config-if-range)# exit
```
*Explanation:* Sets ports as trunks and explicitly removes VLAN 999 from being carried across the link for security.

**Verification on SW1:**
```bash
Switch# show vlan brief
Switch# show interfaces trunk
```

## Troubleshooting

**Issue Encountered:**  
Spanning Tree Protocol (STP) errors (`%SPANTREE-2-RECV_PVID_ERR` and port blocking) on trunk ports during initial configuration.

**Root Cause:**  
Trunk mode was not configured on both ends of the link simultaneously, causing temporary native VLAN mismatch/inconsistent port type.

**Fix Applied:**  
Configured `switchport mode trunk` and `switchport trunk allowed vlan except 999` on both switches' connecting ports.

**Lessons Learned:**
- Always configure both ends of a trunk link carefully.
- Use `except` keyword for security when blackholing a VLAN.

## Notes / Real-World Insights

### Best Practices
- Never use VLAN 1 for user traffic (keep it empty or for management only).
- Always use a dedicated blackhole VLAN for unused ports.
- Explicitly define `allowed vlan` lists on trunks.
- Document VLAN naming convention across the organization.

### Common Mistakes
- Forgetting to configure both sides of a trunk.
- Leaving unused ports in default VLAN 1.
- Using `switchport trunk allowed vlan all` in production.

### Enterprise Usage
In real enterprise environments, these configurations are managed via automation tools (Ansible, Cisco DNA Center) and combined with **port security**, **DHCP snooping**, and **Dynamic ARP Inspection** for comprehensive Layer 2 security.

**Interview Tip:** Be ready to explain why you would use `allowed vlan except 999` instead of manually listing VLANs.
