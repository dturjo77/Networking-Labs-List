# Layer 2 Security Hardening: Native VLAN Change, DTP Disable, and CDP Disable on a Three-Switch Topology

---

## 1. Lab Title

**Layer 2 Security Hardening: Disabling DTP, Changing Native VLAN, and Disabling CDP Across a Three-Switch Network**

---

## 2. Lab Objective

This lab demonstrates a practical Layer 2 security hardening workflow applied consistently across three interconnected switches. The lab covers three distinct but related security controls: replacing the default native VLAN (VLAN 1) with a dedicated VLAN (VLAN 33), disabling Dynamic Trunking Protocol (DTP) negotiation on all ports, and disabling Cisco Discovery Protocol (CDP) globally.

**Skills and concepts practiced:**

- Creating dedicated native and user VLANs on multiple switches
- Configuring access ports in bulk using interface ranges and disabling DTP on those ports
- Configuring trunk ports in bulk and changing the native VLAN to a non-default VLAN
- Applying `switchport nonegotiate` to prevent DTP-based trunk formation
- Disabling CDP globally with `no cdp run`
- Recognizing, understanding, and resolving STP PVID inconsistency errors
- Understanding CDP native VLAN mismatch warnings and their significance
- Applying consistent security hardening across all switches in a topology

---

## 3. Concept Explanation

### Concept 1: Native VLAN Hardening

As established in prior labs, the native VLAN is the VLAN that carries **untagged traffic** on an 802.1Q trunk. The default is VLAN 1. Changing it to a dedicated, unpopulated VLAN (VLAN 33 in this lab) mitigates **double-tagging VLAN hopping** attacks, where an attacker crafts frames with two 802.1Q headers to inject traffic into the native VLAN of a remote switch.

The security rule is simple: **the native VLAN should have no end hosts, no SVIs, and no management traffic assigned to it.** It exists only to carry the mandatory untagged traffic on trunk links.

### Concept 2: DTP — Dynamic Trunking Protocol

**DTP (Dynamic Trunking Protocol)** is a Cisco proprietary protocol that allows switch ports to automatically negotiate whether to form a trunk link with a neighboring device. By default, many Cisco switch ports are in `dynamic auto` or `dynamic desirable` mode, meaning they will form a trunk if the neighbor agrees.

**Why this is a security risk:** An attacker who connects a rogue switch or a device configured to send DTP frames to a port can cause that port to form a trunk automatically. Once trunking, the rogue device has access to all VLANs on that trunk — bypassing access port VLAN segmentation entirely. This is known as a **switch spoofing** attack.

`switchport nonegotiate` disables DTP frame generation and processing on a port. Combined with explicitly setting the port mode (`access` or `trunk`), it ensures the port mode is statically defined and cannot be changed by a neighbor's DTP negotiation.

### Concept 3: CDP — Cisco Discovery Protocol

**CDP (Cisco Discovery Protocol)** is a Cisco proprietary Layer 2 protocol that allows Cisco devices to discover directly connected neighbors and share information including:

- Device hostname
- IOS version
- Platform/model
- Interface IP addresses
- Native VLAN information

**Why this is a security risk:** CDP sends detailed device information in plaintext multicast frames on all interfaces by default. Any device connected to the network — including unauthorized devices — can passively receive CDP advertisements and gather a detailed inventory of the network infrastructure without authentication. This information is directly useful for planning targeted attacks.

`no cdp run` disables CDP globally on the switch, preventing it from sending or processing CDP frames on any interface.

### Real-World Application

In enterprise security hardening guides (CIS Benchmarks, NSA Cisco Router and Switch Security Guide, Cisco SAFE), disabling DTP and CDP on all user-facing ports and disabling CDP globally on switches that do not require it are **baseline hardening requirements** — not optional configurations.

### Advantages

- Eliminates DTP-based switch spoofing attack vector
- Eliminates CDP-based network reconnaissance
- Native VLAN change mitigates double-tagging VLAN hopping
- All three controls together represent a complete Layer 2 access port hardening profile

### Limitations

- Disabling CDP breaks tools and protocols that rely on neighbor discovery (e.g., Cisco IP Phone auto-configuration, some NMS systems). Evaluate per-interface if full disable is not appropriate.
- `switchport nonegotiate` must be combined with a static port mode (`access` or `trunk`) — it does not work alone on ports still in dynamic mode.
- Native VLAN change must be applied consistently across both ends of every trunk link — a mismatch causes STP port blocking.

## 5. Step-by-Step Configuration

---

### Device: SW1 — Core Switch (VLAN 10 — IT)

#### Step 1 — VLAN Creation

```bash
Switch> en
Switch# conf t
Switch(config)# hostname SW1
```
**Explanation:** Enters configuration mode and sets the hostname. The hostname is used by CDP and appears in all log messages — essential for identifying which device generated which messages.

```bash
SW1(config)# vlan 10
SW1(config-vlan)# name IT
SW1(config)# vlan 33
SW1(config-vlan)# name NATIVE
SW1(config-vlan)# exit
```
**Explanation:** Creates VLAN 10 for IT department end devices and VLAN 33 as the dedicated native VLAN. VLAN 33 must be created in the VLAN database before it can be assigned as the native VLAN on trunk ports. It intentionally has no end hosts or SVIs assigned to it.

#### Step 2 — Access Port Hardening (Fa0/5-24, Gig0/1-2)

```bash
SW1(config)# int range fa0/5-24, gig0/1-2
SW1(config-if-range)# switchport mode access
SW1(config-if-range)# switchport access vlan 10
SW1(config-if-range)# switchport nonegotiate
SW1(config-if-range)# exit
```
**Explanation of each command:**

- `switchport mode access` — Statically sets the port to access mode. This is required before `switchport nonegotiate` can take effect. A port in dynamic mode cannot use nonegotiate.
- `switchport access vlan 10` — Assigns all unused ports to VLAN 10 (IT). This prevents unassigned ports from sitting on the default VLAN 1, which carries control-plane traffic.
- `switchport nonegotiate` — Disables DTP frame transmission and reception on the port. Even if a rogue device sends DTP frames, this port will not respond or form a trunk. This blocks switch spoofing attacks on access ports.

#### Step 3 — Trunk Port Configuration and Native VLAN Hardening (Fa0/1-4)

```bash
SW1(config)# int range fa0/1-4
SW1(config-if-range)# switchport mode trunk
SW1(config-if-range)# switchport trunk native vlan 33
SW1(config-if-range)# switchport nonegotiate
SW1(config-if-range)# exit
```
**Explanation of each command:**

- `switchport mode trunk` — Statically sets the port to trunk mode (802.1Q). Required before assigning the native VLAN and applying nonegotiate.
- `switchport trunk native vlan 33` — Changes the native VLAN from the insecure default (VLAN 1) to the dedicated VLAN 33. Untagged frames on this trunk will now be associated with VLAN 33, which has no hosts — neutralizing double-tagging attacks.
- `switchport nonegotiate` — Disables DTP on trunk ports as well. Even trunk ports should not advertise DTP, as this reveals the port is trunking and accepts negotiation requests.

**Immediately after this command, STP resolves the prior blocking condition:**
```
%SPANTREE-2-UNBLOCK_CONSIST_PORT: Unblocking FastEthernet0/1 on VLAN0033. Port consistency restored.
%SPANTREE-2-UNBLOCK_CONSIST_PORT: Unblocking FastEthernet0/1 on VLAN0001. Port consistency restored.
(repeated for Fa0/2, Fa0/3, Fa0/4)
```
**Explanation:** SW3 had already configured native VLAN 33 on its trunk ports before SW1. As soon as SW1's trunk ports were also set to native VLAN 33, STP detected that both ends now agree — it automatically unblocked the ports. No manual intervention was required.

#### Step 4 — Disable CDP Globally

```bash
SW1(config)# no cdp run
```
**Explanation:** Disables CDP on all interfaces globally. SW1 will no longer send CDP advertisements or process incoming CDP frames from any neighbor. This prevents unauthorized devices from harvesting network topology information (hostname, IOS version, platform, IP addresses, native VLAN) from CDP broadcasts.

#### Step 5 — Save Configuration

```bash
SW1(config)# do wr
```
**Explanation:** Saves the running configuration to NVRAM. All security hardening applied in this session will persist after a reload.

## 7. Troubleshooting

### Issue 1: STP PVID Inconsistency — Ports Blocked Before Trunk Mode Was Applied

**Error Messages (SW1 and SW2 before trunk configuration):**
```
%SPANTREE-2-RECV_PVID_ERR: Received 802.1Q BPDU on non trunk FastEthernet0/1 VLAN1.
%SPANTREE-2-BLOCK_PVID_LOCAL: Blocking FastEthernet0/1 on VLAN0001. Inconsistent port type.
```

**Root Cause:** SW3 had already configured its ports as trunks before SW1 and SW2 configured theirs. When SW3 sent 802.1Q-tagged BPDUs out of its trunk ports, the receiving ports on SW1 and SW2 were still in their default access/dynamic mode. A non-trunk port receiving 802.1Q BPDUs is a PVID inconsistency — STP blocked the ports immediately.

**Fix Applied:** SW1 and SW2 applied `switchport mode trunk` on Fa0/1-4, which aligned the port mode with what SW3 was already sending. STP automatically unblocked the ports.

**Lesson Learned:** In a multi-switch lab, configure trunk ports on all switches before configuring native VLANs. The safest sequence is: (1) create VLANs, (2) configure access ports, (3) configure trunk mode on all switches, (4) change native VLAN on all switches.

---

### Issue 2: STP PVID Inconsistency — Native VLAN Mismatch After Partial Configuration

**Error Messages (after SW3 set native VLAN 33 but before SW1/SW2 did):**
```
%SPANTREE-2-RECV_PVID_ERR: Received BPDU with inconsistent peer vlan id 33 on FastEthernet0/1 VLAN1.
%SPANTREE-2-BLOCK_PVID_LOCAL: Blocking FastEthernet0/1 on VLAN0001. Inconsistent local vlan.
```

**Root Cause:** SW3 was the first to apply `switchport trunk native vlan 33`. SW1 and SW2 were still at native VLAN 1. The mismatch caused STP to block the inconsistent ports.

**Fix Applied:** SW1 applied `switchport trunk native vlan 33`, which immediately unblocked all four trunk ports as confirmed by the `UNBLOCK_CONSIST_PORT` messages.

**Lesson Learned:** Native VLAN changes must be applied to both ends of a trunk simultaneously in production. In a maintenance window, configure the far end first if possible, or apply both ends within the same change session to minimize the blocking window.

---

### Issue 3: Incomplete CDP Disable Command on SW3

**What Happened:**
```
SW3(config)# no cdp
% Incomplete command.
```

**Root Cause:** The complete command is `no cdp run`. The shortened `no cdp` is ambiguous as it could apply to several CDP subcommands.

**Fix Applied:** Entered the full command `no cdp run`.

**Lesson Learned:** When disabling protocols globally in IOS, always use the full command. Partial commands for disable operations are frequently ambiguous.

---

### Issue 4: Invalid VLAN Command on SW1

**What Happened:**
```
SW1(config-vlan)# vlan
                  ^
% Invalid input detected at '^' marker.
```

**Root Cause:** The `vlan` command requires a VLAN ID as an argument. Entering `vlan` alone with no number is invalid.

**Fix Applied:** The engineer entered `vlan 33` on the next attempt.

## 8. Conclusion

This lab successfully demonstrated a complete Layer 2 security hardening workflow across three interconnected switches. All three security controls — native VLAN change, DTP disable, and CDP disable — were applied consistently across every switch and every port role (access and trunk).

Key outcomes:

- **Native VLAN 33** replaced the insecure default VLAN 1 on all trunk links across the full topology, eliminating the double-tagging VLAN hopping attack surface.
- **`switchport nonegotiate`** was applied to both access and trunk ports on all three switches, ensuring that no port can be coerced into a different mode by DTP negotiation — blocking switch spoofing attacks.
- **`no cdp run`** was applied globally on all three switches, preventing network topology reconnaissance via CDP advertisements.
- The STP PVID blocking behavior during partial configuration demonstrated — concretely — why native VLAN changes must be coordinated across both ends of every trunk link.

## 9. Notes / Real-World Insights

### Best Practices

- **Apply hardening in a consistent, documented sequence.** The recommended order for Layer 2 hardening is:
  1. Create all VLANs (including the dedicated native VLAN)
  2. Configure access ports — mode, VLAN assignment, nonegotiate
  3. Configure trunk ports — mode, native VLAN, nonegotiate
  4. Disable CDP globally or per-interface as required
  5. Save configuration

- **Consider per-interface CDP disable rather than global.** If any Cisco IP phones, network management systems, or other CDP-dependent devices are in the network, `no cdp run` globally will break their functionality. Use `no cdp enable` on specific user-facing interfaces while leaving CDP active on inter-switch links where it is needed for management.

  ```bash
  interface fa0/5
  no cdp enable
  ```

- **Assign unused ports to a dedicated "black hole" VLAN** that has no SVI, no routing, and is not the native VLAN. VLAN 999 is a common convention.

  ```bash
  vlan 999
  name UNUSED
  interface range fa0/5-24
  switchport access vlan 999
  shutdown
  ```

- **Add `ip dhcp snooping` and `dynamic arp inspection`** as the next hardening steps after DTP and CDP are disabled. These controls prevent DHCP starvation and ARP poisoning — the two most common Layer 2 data-plane attacks.

### Common Mistakes

| Mistake | Consequence |
|---|---|
| Applying `switchport nonegotiate` without first setting a static mode | Command is rejected on dynamic mode ports; DTP remains active |
| Changing native VLAN on one end of a trunk without the other | STP PVID blocking — traffic disruption until both ends match |
| Disabling CDP globally when IP phones are in use | IP phones lose auto-configuration (voice VLAN, QoS) |
| Leaving unused ports on VLAN 1 with no shutdown | Active, unmonitored ports on the management VLAN — a security gap |
| Using `no cdp` without `run` | Ambiguous command error — CDP remains active |

### Security Attack Vectors Addressed by This Lab

| Attack | Mitigation Applied |
|---|---|
| Double-tagging VLAN hopping | Native VLAN changed from VLAN 1 to VLAN 33 |
| Switch spoofing (DTP-based trunk formation) | `switchport nonegotiate` on all ports |
| Network reconnaissance via CDP | `no cdp run` globally on all switches |

### Interview and Job Tips

- "What is DTP and why is it a security risk?" is a standard Layer 2 security question at the CCNA/CCNP level. Know that DTP allows automatic trunk formation and that `switchport nonegotiate` disables it.
- Know the three Layer 2 VLAN hopping attack types: **switch spoofing** (DTP exploitation), **single-tagging** (accessing native VLAN from an access port), and **double-tagging** (two 802.1Q headers to jump native VLANs). Each has a specific mitigation.
- Be ready to explain why `switchport nonegotiate` must be paired with a statically set port mode — this is frequently tested in lab-style interview questions.
- In enterprise audits and security assessments (penetration tests), the first checks performed against a switched network are DTP probing, CDP harvesting, and native VLAN verification. Knowing these from the defender's perspective is directly applicable to security engineering roles.
- The full Cisco Layer 2 hardening checklist also includes: disabling unused ports, enabling BPDU Guard on access ports, enabling Root Guard on designated ports, enabling port security, and enabling DHCP snooping. This lab covers three of those controls.
