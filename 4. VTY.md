**Lab Name:** VTP (VLAN Trunking Protocol) Configuration with Multiple VTP Modes

### 1. Lab Objective
This lab aims to configure and demonstrate **VLAN Trunking Protocol (VTP)** across multiple switches operating in different VTP modes (Server, Client, and Transparent). It shows how VLAN information propagates automatically and how local VLANs can be created independently.

**Skills/Concepts Practiced:**
- VTP domain, password, version, and mode configuration
- Trunk port setup for VTP advertisements
- Understanding differences between VTP Server, Client, and Transparent modes
- VLAN creation and propagation
- Troubleshooting VTP and trunking issues

### 2. Concept Explanation (In-depth)

**What is VTP?**  
VLAN Trunking Protocol (VTP) is a Cisco proprietary protocol that allows central management of VLANs. VLANs created on a VTP Server are automatically advertised and synchronized to VTP Client switches in the same domain.

**Why it is used in real networks?**  
Managing VLANs manually on dozens or hundreds of switches is time-consuming and error-prone. VTP simplifies VLAN administration across the entire network.

**How it works internally (simple explanation):**  
- A VTP Server creates/modifies VLANs and sends advertisements over **trunk links**.
- VTP Clients receive and apply these updates but cannot create VLANs locally.
- VTP Transparent mode switches forward VTP advertisements but do not apply them — they maintain their own local VLAN database.

**Real-world example:**  
In a large campus network with 50+ switches, the core switch is set as VTP Server. When the network team adds a new VLAN for "Voice" or "Guest", it is automatically created on all client switches, saving significant time and reducing configuration mistakes.

**Key Advantages:**
- Centralized VLAN management
- Reduced administrative overhead
- Consistent VLAN configuration across switches

**Limitations:**
- Risk of VLAN deletion if someone accidentally deletes a VLAN on the Server
- VTP can cause issues if domain name/password mismatches occur
- Transparent mode is often preferred in modern networks for better security and control

### 4. Step-by-Step Configuration

#### SW0 (VTP Server)
```bash
SW0(config)#vtp mode server               // Sets the switch as the master for VLAN changes
SW0(config)#vtp domain cisco.com          // Defines the VTP domain name (must match on all switches)
SW0(config)#vtp password cisco            // Sets VTP password for security (prevents unauthorized updates)
SW0(config)#vtp version 2                 // Enables VTP version 2 (supports more features)

SW0(config)#vlan 10
SW0(config-vlan)#name IT                  // Creates VLAN 10
SW0(config-vlan)#vlan 20
SW0(config-vlan)#name HR
SW0(config-vlan)#vlan 30
SW0(config-vlan)#name CS

SW0(config)#interface range fa0/1-2
SW0(config-if-range)#switchport mode trunk   // Configures ports as trunks to carry VLANs and VTP messages
```

#### SW1 & SW2 & SW3 (VTP Clients)
```bash
SW1(config)#vtp mode client               // Cannot create VLANs locally; receives from Server
SW1(config)#vtp domain cisco.com
SW1(config)#vtp password cisco

SW1(config)#interface fa0/3
SW1(config-if)#switchport mode access
SW1(config-if)#switchport access vlan 20  // Assigns port to HR VLAN (propagated from Server)

SW1(config)#interface fa0/4
SW1(config-if)#switchport mode access
SW1(config-if)#switchport access vlan 30
```

(Similar trunk and access port configurations were done on SW2 and SW3)

#### SW4 (VTP Transparent)
```bash
SW4(config)#vtp mode transparent          // Forwards VTP messages but keeps local VLAN database independent
SW4(config)#vtp domain cisco.com
SW4(config)#vtp password cisco

SW4(config)#vlan 50
SW4(config-vlan)#name MN                  // Local VLAN — not propagated to other switches
SW4(config-vlan)#vlan 99
SW4(config-vlan)#name DHCP

SW4(config)#interface fa0/2
SW4(config-if)#switchport mode access
SW4(config-if)#switchport access vlan 50

SW4(config)#interface fa0/1
SW4(config-if)#switchport mode trunk      // Still needs trunk to forward VTP advertisements
```

### 6. Troubleshooting

**Problems Faced:**

1. **Problem:** `%SPANTREE-2-RECV_PVID_ERR` and port blocking  
   **Cause:** Connecting trunk to a non-trunk port (native VLAN mismatch / port type inconsistency)  
   **Fix:** Configured matching `switchport mode trunk` on both ends.

2. **Problem:** VLANs not appearing on Client switches  
   **Cause:** VTP domain/password mismatch or no trunk link  
   **Fix:** Corrected domain name and ensured trunk links were active.

3. **Problem:** Cannot create VLAN on Client switch  
   **Cause:** Normal behavior in Client mode  
   **Fix:** Created VLANs on Server (SW0) instead.

4. **Problem:** VTP version change failed on Client  
   **Cause:** Clients cannot change VTP version independently  
   **Fix:** Version set on Server.

This lab successfully demonstrated VTP operation across Server, Client, and Transparent modes. VLANs created on the Server were automatically propagated to Client switches, while the Transparent switch maintained local VLANs independently.

**Key Takeaways:**
- VTP simplifies large-scale VLAN management
- Proper trunk configuration is essential for VTP
- Transparent mode provides flexibility and safety

### Notes / Real-World Insight
- Many modern networks prefer **VTP Transparent** or **VTP Off** mode for better security (prevents accidental VLAN deletion).
- Always use a strong VTP password.
- Monitor VTP revision number — a higher revision can overwrite the entire VLAN database.
- Best practice: Document VTP domain and maintain a backup of VLAN configurations.
